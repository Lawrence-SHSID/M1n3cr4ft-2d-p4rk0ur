# 游戏设计大纲

更新日期：2026-10-06（Asia/Shanghai）。用户要求以 [DECISIONS.md](DECISIONS.md) 为准；被否决或替换的方案见 [REJECTED.md](REJECTED.md)。本文件同时描述实现现状，具体默认值不应自动视为用户确认。

## 产品与核心循环

项目当前名称为 **Skybound**，名称由助手选定。它是 Minecraft 风格但不完全照搬的二维天空岛跑酷游戏。

玩家从起点出发，穿过岛屿、缺口、尖刺与移动平台，抵达红旗终点。游玩时玩家不能放置、移动、破坏或修改方块，移动平台由游戏自动控制。M15 新增独立编辑器，允许在游玩之外创建自己的关卡；不把早期游玩限制误用于阻止用户的新建关卡要求。

第一关横向长度为 10 格，常规横向课程每关增加 5 格：length = 10 + 5 × (level − 1)。2026-10-03 用户后来要求 Nether 向上折返：第 11–19 关保留 length 作为课程规模和检查点资格指标，实际横向宽度改由 width 表示（11–13 格）；界面显示实际攀升高度。此适配是对新要求的实现选择，不把旧横向要求改写为用户从来未要求。跳高和课程长度仍是独立指标。

Steve 与 Alex 使用代码绘制的像素人物，走路时四肢摆动。Alex 的橙发、绿衣和 Steve 的蓝衣用于区分玩家。

行走时脚下产生与方块颜色相应的小颗粒；冲刺时更密集。颗粒在世界坐标中漂移并消失，暂停时冻结；复活不会生成跨地图的拖尾。

## 普通跑酷控制

| 玩家 | 左右移动 | 跳跃 | 蹲下 | 冲刺 |
| --- | --- | --- | --- | --- |
| Steve | ←／→ | ↑ | ↓ | 双击并按住 ← 或 → |
| Alex，双人模式 | A／D | W | S | 双击并按住 A 或 D |

单人模式当前允许方向键或 WASD 操作 Steve；这是保留的实现便利。Alex 的 W／S 与 Steve 的 ↑／↓ 对应，属于 WASD 分工的实现映射。

普通跳跃高度由初始 1 格改为 **1.2 格**（2026-10-03 用户要求）。普通跳跃配合冲刺能跨越 4 格空隙，不能跨越 5 格；史莱姆跳跃高度为 5 格。用户关于冲刺上限的原要求与史莱姆水平跨度的未明确边界，另见确定方案中的备注。

蹲下当前同时降低角色高度、减速并防止从平台边缘直接走落；仍可主动跳跃。双击窗口目前为 250 ms，需松开后再次按下同一方向键。松开冲刺方向、改按反向或蹲下会结束冲刺。这些具体细节属于实现默认值。

R 从个人检查点重试；未保存检查点则回起点。重置按钮从头重开整关并清除该关检查点。Esc 暂停整个会话。单人提供触摸控制。

## 多人模式与共享镜头

支持单人与同键盘本地双人。Steve 使用方向键，Alex 使用 WASD。2026-10-06 用户要求多人分为 Teamwork 与 PK：Teamwork 保留双方都抵达红旗才过关；PK 当前实现为先抵达红旗者获胜的竞速。两名玩家仍无相互碰撞。先到获胜、同一物理步平局、同一起跑坐标属于助手采用的具体竞速规则，不冒充用户逐项确认。

单人失败后显示重试界面。双人中失败的玩家约 0.8 秒后独立复活，另一玩家可以继续行动。双方检查点独立保存。

**只使用一张共享地图、一个画布。** Steve 与 Alex 靠近时平滑放大，分开时平滑缩小；同时考虑横向与纵向距离。先到终点的玩家继续参与镜头构图。

角色复活等待期间，镜头提前考虑其检查点位置，平滑准备缩放与移动，同时保持仍在行动或已到终点的玩家可见。普通移动不使用突然切换视图。单人镜头跟随 Steve。

## 普通关卡与检查点

关卡不能只是同一段路线重复加长。当前前七关为不同的手工布局：初学跳跃与史莱姆、四格冲刺缺口、森林阶梯、水平石板渡船、上升与下降路线、综合挑战、冰面滑行（第 7 关 Frostline crossing）。之后使用确定性种子混合地形、高度、缺口和平台。

这些具体布局和生成方法由助手选定，用于满足用户对关卡变化的要求。当前生成范围为 1–1000 关；1000 关上限不是用户要求。

检查点只在长度 **大于 45 格** 的关卡出现，即从第 9 关的 50 格开始。第 8 关为 45 格，没有检查点。

普通关卡的检查点放在安全静态草地，避开尖刺与狭窄单格落脚点；飞行关卡的检查点位于开阔空中，以青色圆环表示。当前大致每 20 格安排一个检查点，这是实现选择。标记会显示 S／A，表示 Steve／Alex 已保存。

## 每十关的鞘翅飞行

第 10、20、30……关为 `elytra` 飞行关卡，横向长度仍遵循每关加 5 格。Steve 展开鞘翅，以类似 Geometry Dash 飞船模式的方式自动向右滑翔。

| 操作 | Steve | 双人中的 Alex |
| --- | --- | --- |
| 向上升起 | 按住 ↑ | 按住 W |
| 加快前进 | 按住 → | 按住 D |
| 向下降落 | 松开升力键／不按键 | 松开升力键／不按键 |

Alex 的飞行支持是助手为保持双人模式一致性增加的实现选择。升力与重力平滑改变纵向速度；飞行中不用蹲下或双击冲刺。

飞行路线使用交替从上、下伸出的石柱和宽阔通道。接触石柱或飞行边界立即失败。抵达终点通过安全地飞越终点横向位置判定，不要求在红旗下落地；这是实现选择。

飞行镜头保持完整纵向通道可见，同时按两名玩家的横向距离平滑缩放。飞行检查点恢复新的飞行身体与零纵向速度，距下一道石柱至少 5 格，确保正常和加速状态都有调整方向的时间。

## 技术结构与资源

前端为 Vue 3 + TypeScript + Vite，后端为 Node.js。Vue 管理界面，Canvas 绘制世界，固定 120 Hz 物理步进处理游戏行为。

| 文件 | 职责 |
| --- | --- |
| `shared/types.ts` | 方块、关卡、角色、检查点与会话类型 |
| `shared/levels.ts` | 普通与飞行关卡生成 |
| `src/game/physics.ts` | 普通跑酷物理与碰撞；按关卡类型分派 |
| `src/game/flight.ts` | 自动滑翔、升力、加速与飞行碰撞 |
| `src/game/session.ts` | 单人／双人会话、独立复活、检查点、共同平台时钟 |
| `src/game/controls.ts` | 键位分工、双击冲刺与短按跳跃队列 |
| `src/game/camera.ts` | 共享镜头位置、缩放和复活预判 |
| `src/game/particles.ts` | 行走颗粒 |
| `src/game/renderer.ts` | 地形、人物、鞘翅、颗粒、旗帜与圆环绘制 |
| `src/App.vue`、`src/style.css` | 界面、输入事件、模式／关卡选择与帮助 |
| `server/index.ts` | 关卡与健康检查 API；提供生产构建文件 |

用户图片已复制到持久资源目录：`public/textures/grass.png`、`dirt.png`、`stone.png`、`tree.png`、`slime.png`。木头与树叶纹理由 `tree.png` 的参考树图片取样，不依赖原临时附件路径。

本地 `npm run dev`：前端端口 5175，API 端口 3005。`npm run build` 后 `npm start` 在 3005 提供生产文件。端口由助手选定，用于避开其他本地项目。

最高完成关卡当前保存在浏览器 `localStorage`；后端提供确定性关卡，无数据库进度存储。该存储方式是实现选择。
